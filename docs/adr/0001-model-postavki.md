# ADR-001: FitClub жобасы үшін жеткізу моделін таңдау

**Күйі:** Қабылданды  
**Күні:** 17.09.2026

## Контекст

FitClub — фитнес-клубтың негізгі процестерін автоматтандыруға арналған ақпараттық жүйе.

Жүйеде клиенттерді тіркеу, абонементтерді басқару, жаттығулар кестесін жүргізу, қатысуды есепке алу және әкімшіге арналған негізгі функциялар қарастырылады.

Жоба оқу семестрі барысында әзірленеді. Бастапқы кезеңде барлық талаптар толық анықталмаған және тапсырыс берушімен жұмыс барысында нақтылануы мүмкін.

Команда төрт адамнан тұрады:

- Аманжол Айдос — Project Manager / Developer;
- Ануар — тапсырыс берушімен коммуникация;
- Адильбек — Analyst / Developer;
- Амир — QA / Tester.

## Қозғаушы факторлар

Жеткізу моделін таңдауға келесі факторлар әсер етеді:

- талаптардың толық анықталмауы;
- тапсырыс берушіден тұрақты кері байланыс алу мүмкіндігі;
- команданың шағын болуы;
- жобаны бірден толық емес, кезең-кезеңімен жасау мүмкіндігі;
- функционалды семестр барысында өзгерту қажеттілігі;
- аралық нәтижелерді көрсетіп, түзетулер енгізу мүмкіндігі.

## Қарастырылған нұсқалар

### 1. Predictive моделі

Predictive тәсілінде барлық талаптар алдын ала толық анықталып, жоба кезеңдері басынан соңына дейін жоспарланады.

**Артықшылықтары:**

- жоба жоспары алдын ала анық болады;
- мерзімдер мен нәтижелерді бақылау оңай;
- жұмыс көлемі ертерек белгіленеді.

**Кемшіліктері:**

- талаптар өзгерсе, жоспарды қайта құру қажет;
- тапсырыс берушінің жаңа ұсыныстарын енгізу қиынырақ;
- оқу жобасы үшін шамадан тыс қатаң болуы мүмкін.

**Неге таңдалмады:**  
FitClub жобасының талаптары әлі толық бекітілмеген және семестр барысында өзгеруі мүмкін.

### 2. Adaptive моделі

Adaptive тәсілінде жоба қысқа итерациялар арқылы орындалады. Әр итерациядан кейін команда нәтижені көрсетіп, тапсырыс берушінің кері байланысын алады.

**Артықшылықтары:**

- талаптарды жұмыс барысында нақтылауға болады;
- өзгерістерге тез бейімделуге мүмкіндік береді;
- тапсырыс берушімен тұрақты байланыс орнатылады;
- аралық нәтиже ертерек көрінеді;
- қателер мен дұрыс емес шешімдер ерте анықталады.

**Кемшіліктері:**

- тапсырыс берушінің тұрақты қатысуын қажет етеді;
- соңғы функционал көлемі бастапқыда толық анық болмайды;
- backlog пен тапсырмалар тақтасын үнемі жаңартып отыру керек.

### 3. Hybrid моделі

Hybrid тәсілі Predictive және Adaptive модельдерінің элементтерін біріктіреді. Негізгі кезеңдер алдын ала жоспарланып, ал функционал итерациялық түрде әзірленеді.

**Артықшылықтары:**

- жалпы жоспар сақталады;
- өзгерістерді белгілі бір деңгейде енгізуге болады;
- ірі жобалар үшін ыңғайлы.

**Кемшіліктері:**

- басқаруы күрделірек;
- шағын студенттік команда үшін артық процесс тудыруы мүмкін;
- қосымша құжаттандыруды талап етеді.

**Неге таңдалмады:**  
FitClub — көлемі шағын оқу жобасы, сондықтан Hybrid моделі артық күрделілік береді.

## Шешім

FitClub жобасы үшін **Adaptive жеткізу моделі** таңдалды.

Команда жобаны қысқа итерациялармен жүргізеді. Әр кезеңде шағын тапсырмалар жиыны орындалып, нәтиже тапсырыс берушіге көрсетіледі. Алынған кері байланыс келесі итерацияны жоспарлау кезінде ескеріледі.

Тапсырмалар GitHub Projects арқылы басқарылады.

## Оң салдарлар

- талаптарды жұмыс барысында өзгертуге және нақтылауға болады;
- тапсырыс беруші аралық нәтижені көре алады;
- қажетсіз функцияларды ерте анықтауға болады;
- команда жұмыс басымдығын өзгерте алады;
- қателер ертерек анықталады.

## Теріс салдарлар

- тапсырыс берушіден тұрақты кері байланыс қажет;
- барлық функционал басында толық анық болмайды;
- команда backlog пен статустарды тұрақты жаңартып отыруы керек;
- итерацияларды дұрыс басқармаса, жұмыс көлемі ұлғаюы мүмкін.

## Қайта қарау критерийі

Бұл шешім келесі жағдайларда қайта қаралады:

- тапсырыс беруші талаптарды толық бекітіп, өзгерістерге рұқсат бермесе;
- жобаға қатаң фиксирленген мерзім немесе келісімшарт талаптары енгізілсе;
- команда құрамы немесе жобаның көлемі едәуір өзгерсе;
- Adaptive тәсілі жобаны басқаруда қиындық туғызса.
