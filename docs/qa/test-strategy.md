# FitClub тестілеу стратегиясы

## 1. Мақсат және сапа тәуекелдері

Мақсат — клиентті тіркеу, абонемент пен төлемді жүргізу кезінде деректің жоғалуын, қайталануын және рөлдердің араласуын болдырмау. Басым тәуекелдер: рұқсатсыз әкімшілік қолжетімділік, бір операцияның екі рет орындалуы, жарамсыз күн/сома және дерекқор қолжетімсіз болғанда жалған `healthy` күйі.

## 2. Тестілеу деңгейлері

| Деңгей | Құрал | Қамту | Орындау сәті |
|---|---|---|---|
| Модульдік/интеграциялық | pytest + Flask test client | авторизация, валидация, SQLite, идемпотенттілік | әр өзгерісте |
| UI smoke | Playwright/Chromium | `/health`, кіру, dashboard, клиенттер | релиз алдында |
| Жүктемелік | k6 Docker image | `/health`, p95 және қате үлесі | стенд тұрақты болғанда |
| Қолжетімділік | Docker healthcheck + Uptime Kuma | қолданба және DB readiness | 60 секунд сайын |
| UAT | басқа команда, браузер | 10 бизнес-сценарий | инкремент дайын болғанда |

Автоматтандыру бірінші кезекте қайталанатын және жоғары тәуекелді тексерулерге беріледі. Визуалдық түсініктілік пен бизнес-қабылдау UAT-та қолмен тексеріледі.

## 3. Орта және тест деректері

- Негізгі тест ортасы: Docker Compose, Python 3.13, Flask, жеке SQLite volume.
- Автотест әр тестке уақытша жаңа SQLite файлын жасайды және соңында жояды.
- Демо деректер ойдан шығарылған тұлғалардан тұрады; карта нөмірі, ЖСН және нақты клиент құпиясөзі сақталмайды.
- UAT үшін бөлек байланыс мәндері қолданылады: `uat-<күні>-<нөмір>@example.test`.
- UAT аяқталғаннан кейін тест volume жойылады немесе жаңадан құрылады.

## 4. Кіру және шығу критерийлері

**Кіру:** код іске қосылады; дерекқор инициализацияланған; `/health` — 200; әкімші тест жазбасы бар; сценарийлер мен күтілетін нәтиже бекітілген.

**Шығу:** pytest және UI smoke толық өтеді; k6 threshold орындалады; Severity 1–2 ашық ақау жоқ; UAT сценарийлерінің 100%-ы орындалған; қабылдаушының шешімі хаттамада бар.

## 5. Дефект басқару

| Severity | Мағына | Мысал | Түзету SLA |
|---|---|---|---|
| S1 Critical | жүйе/дерек толық қолжетімсіз немесе қауіпсіздік бұзылды | барлық кіру тоқтады | 4 сағат |
| S2 Major | негізгі бизнес-функция жұмыс істемейді | төлем тіркелмейді | 1 жұмыс күні |
| S3 Minor | айналып өту жолы бар | іздеу мәтіні түсініксіз | 3 жұмыс күні |
| S4 Trivial | косметикалық мәселе | аралық/түстің қатесі | келесі жоспарлы релиз |

Priority: P1 — дереу, P2 — келесі итерация, P3 — backlog. Severity әсерді, Priority орындау кезегін білдіреді. Әр түзетуден кейін ақау қайта тексеріліп, оған жақын автоматты регресс орындалады.

## 6. Жауапкершілік

- **Айдос:** орта, код, автоматтандыру, ақауды түзету.
- **Әділбек:** тест дизайны, орындау дәлелі, регресс және `/health` мониторингі.
- **Ануар:** басқа командамен UAT уақытын келісу, қабылдау шешімі және коммуникация.
